# リスク／不確実性（現時点）

## R1：外部サイトのHTML構造変更
- 影響：候補取得が壊れて9枠が埋まらない
- 対策：
  - 取得対象は「一覧／検索結果」に限定し、ページ解析を最小化
  - 解析失敗時は「候補不足警告＋フォールバック」で落とさない
  - 候補プールをキャッシュし、毎回外部に依存しない

## R2：CORS・取得経路の問題
- 影響：ブラウザ（iPhone）から直接fetchできず、候補取得が動かない
- 対策：
  - 取得・解析はサーバー側（API/Function）またはビルド時に寄せる
  - 現行スタックに合わせて最小の実装方式を選ぶ（OPEN_QUESTIONS参照）

## R3：アクセス負荷（レート制限・速度）
- 影響：生成が遅い、アクセスが拒否される
- 対策：
  - 候補取得頻度を抑える（週1/日1/手動更新）
  - 取得件数を上限設定し、タイムアウトしたら部分結果で埋める

## R4：30分目安の信頼性
- 影響：実体験として“手間が多い”レシピが混ざる
- 対策：
  - まずは「要注意」表示（煮込み/寝かせ等キーワード）で開始
  - POが実運用で許容ラインを決める

## R5：端末間の設定共有
- 影響：iPhoneとiPad、夫婦間で設定が一致しない
- 対策：
  - まずはコピー&ペーストのエクスポート/インポートで開始（P1）
  - 必要が出てから同期（ログイン等）を検討

## R6：食材の使い回し戦略の“機械判定”難易度
- 影響：狙った通りに食材が揃わない
- 対策：
  - 最初は「旬食材＝検索語」による簡易戦略
  - “2回使う”を厳格制約にせず、加点（優先）として扱う
