# 開発プロセス（AIエージェント前提のWorking Agreement）

## 1. 役割
- PO：何を作るか（優先順位・受け入れ判断）
- 開発リード兼スクラムマスター：どう進めるか（スプリント計画、分割、リスク管理）
- 実装：Web/VSCode上のAIエージェント（Issue→PR→レビュー→マージ）

## 2. 進め方（スプリント）
- 1スプリント＝1週間を基本（調整可）
- スプリント開始：Sprint Goal と Sprint Backlog を確定
- 日次：PRレビューとブロッカー解消を優先
- 終了：iPhoneでの動作確認（デモ）→次スプリントへ

## 3. Definition of Ready（Issueを着手可能にする条件）
- 背景が2〜3行で書かれている
- やること／やらないことが明確
- 受け入れ条件が3〜5点で検証可能
- UIの期待がある場合はスクショや文章で明記

## 4. Definition of Done（マージ可能の条件）
- iPhone Safariで最低限の動作確認ができる（該当箇所）
- 受け入れ条件を満たす
- 主要な例外系（取得失敗・候補不足）が落ちずに表示できる
- PR本文に「何を変えたか／どう確認するか」が書かれている

## 5. PR運用
- 1PR＝1目的（小さく）
- 競合を避けるため、同じファイルを大きく触る作業は並列しない
- マージ前にPOがiPhoneで確認できる導線（URL/手順）をPRに書く

## 6. データ取り扱いの原則（当面）
- アプリが扱うのは原則「タイトル・URL・出典・警告」まで
- レシピ本文（材料・手順など）をアプリに取り込むのは将来検討（別途設計）

## 7. 仕様の一次ソースと管理
- **決定事項の一次ソース**: 各Sprintのドキュメント（例：`docs/sprints/SPRINT_02.md`）
- **Issueの位置づけ**: 実装タスクの単位。前提となる決定事項はSprint docを参照
- **用語の統一**: Sprint docで確定した用語を使用（例：「必須食材」=「食材プール」）
- **変更時の運用**: 仕様変更が必要な場合は、まずSprint docを更新してから実装Issueを作成
