# Notion データモデル定義（Recipes / Meal Logs）

## 概要

kondate_maker の Notion 連携では、以下の2つのデータソースを使用します：

1. **Recipes（レシピカード）** - レシピの基本情報と評価を管理
2. **Meal Logs（献立履歴）** - いつ何を食べたかの履歴を記録

これらのデータソースは、Notion API 2025-09-03 版の `data_source_id` ベースのモデルに準拠します。

## 1. Recipes（レシピカード）データソース

### 目的
- レシピの基本情報（名前、URL、調理時間など）を一元管理
- レシピの評価を蓄積し、献立選定時の優先度判定に活用
- 買い出しや食材管理の補助情報を保持

### プロパティ定義

| プロパティ名 | 型 | 必須 | 用途 | 備考 |
|------------|-----|------|------|------|
| Name | Title | ✅ 必須 | レシピ名 | Notionのタイトルプロパティ |
| URL | URL | 任意 | レシピのURL | 外部サイトへのリンク |
| Rating | Number | 任意 | レシピ評価（1〜5） | 未評価時はデフォルト3として扱う |
| Ingredients | Multi-select | 任意 | 主な食材タグ | 買い出しや食材管理に使用 |
| Category | Select | 任意 | カテゴリ（主菜/副菜/汁物など） | 献立バランス調整に使用 |
| CookTimeMin | Number | 任意 | 調理時間（分） | 時短レシピの選定に使用 |
| Active | Checkbox | 任意 | 有効フラグ | false時は候補から除外（デフォルト: true） |

### 運用ルール

#### 評価スケール
- **スケール**: 1〜5（5段階評価）
  - 5: 非常に美味しい、また食べたい
  - 4: 美味しい、定期的に作りたい
  - 3: 普通、たまに作ってもよい（デフォルト値）
  - 2: イマイチ、あまり作りたくない
  - 1: 失敗、次回は避けたい

- **未評価の扱い**
  - Ratingプロパティが空欄の場合、デフォルト値として **3（普通）** を使用
  - これにより、新規レシピも既存レシピと同等に選定候補に含まれる
  - 実際に作って評価した後、Ratingを更新することで優先度が変動

#### 除外フラグの運用
- **Activeプロパティ**: レシピを一時的に除外したい場合に使用
  - デフォルト: true（有効）
  - false に設定すると、献立選定の候補から除外される
  - 用途例：
    - 季節外れのレシピ（夏場の鍋、冬場の冷やし中華など）
    - 食べ飽きたレシピの一時的な除外
    - 特定の理由で作れないレシピ（食材入手困難など）

## 2. Meal Logs（献立履歴）データソース

### 目的
- いつ何を食べたかの履歴を記録
- 直近の重複を避けるための判定根拠を提供
- 食後評価を記録し、Recipes の Rating 更新の参考にする

### プロパティ定義

| プロパティ名 | 型 | 必須 | 用途 | 備考 |
|------------|-----|------|------|------|
| Date | Date | ✅ 必須 | 食べた日付 | 直近抑制の判定根拠 |
| Recipe | Relation | ✅ 必須 | レシピへの参照 | Recipes データソースとのリレーション |
| RatingAfter | Number | 任意 | 食後評価（1〜5） | Recipes の Rating とは別管理 |
| Memo | Text | 任意 | メモ | 調整内容や感想などを自由記述 |

### 運用ルール

#### 直近の定義と抑制ロジック
- **直近期間**: 過去 **14日間**
  - Meal Logs の Date プロパティが「今日から14日以内」のレシピは、直近として扱う
  - 直近のレシピは献立選定時の優先度を下げる（完全除外はしない）

- **候補不足時の緩和方針**
  - 直近抑制を適用すると候補が不足する場合（必要枠数を満たせない場合）：
    1. 警告メッセージを表示
    2. 直近抑制を緩和し、全候補プールから選定する
    3. ユーザーは手動で差し替えるか、そのまま使用するかを判断
  - 緩和の段階：
    - Level 1: 直近14日 → 直近7日に短縮
    - Level 2: 直近抑制を解除（全候補から選定）

#### 食後評価の運用
- **RatingAfter**: 実際に作って食べた後の評価を記録
  - Recipes の Rating と別管理にすることで、以下が可能：
    - 同じレシピでも調理タイミングや体調により評価が変動する記録
    - 複数回の食後評価の平均から Recipes の Rating を更新する判断材料
  - 運用例：
    - 献立作成時は Recipes の Rating（平均評価）を参照
    - 食後に RatingAfter を記録
    - 定期的に RatingAfter の平均を Recipes の Rating に反映

## 3. data_source_id の管理

### data_source_id とは
Notion API 2025-09-03 版では、データベースを識別するために `data_source_id` を使用します。
これは従来の `database_id` に相当しますが、より柔軟なデータソース（DB、ページ、Wiki など）を識別できます。

### 取得方法
1. Notion の Web UI で対象のデータベースを開く
2. データベースの「・・・」メニューをクリック
3. 「Manage data sources」セクション（メニュー下部）を探す
4. データソースの横にある三点メニュー（⋮）から「Copy data source ID」を選択
5. クリップボードにコピーされた ID（UUID形式）を保存

💡 **ヒント**: シンプルなデータベース（単一データソース）の場合、「・・・」メニューに直接「Copy data source ID」が表示されることもあります。

### 保存場所
- **GitHub Secrets** に保存（推奨）
  - `NOTION_RECIPES_DATA_SOURCE_ID`: Recipes データソースの ID
  - `NOTION_MEAL_LOGS_DATA_SOURCE_ID`: Meal Logs データソースの ID
  - セキュリティ: プライベート情報として保護され、ログに出力されない

- **代替案: GitHub Variables**
  - パブリックリポジトリでも ID 自体は秘匿性が低い場合は Variables でも可
  - ただし、Integration token は必ず Secrets で管理すること

### 必要な ID 一覧
- `NOTION_TOKEN`: Notion Integration の API トークン（Secret）
- `NOTION_RECIPES_DATA_SOURCE_ID`: Recipes データソースの ID（Secret または Variable）
- `NOTION_MEAL_LOGS_DATA_SOURCE_ID`: Meal Logs データソースの ID（Secret または Variable）

## 4. 個人データの取り扱い方針

### 基本方針
- **Public リポジトリにコミットしてはいけないデータ**：
  - Notion Integration トークン
  - data_source_id（念のため Secrets 管理推奨）
  - レシピの詳細情報（タイトル、URL、評価など）
  - 献立履歴の実データ

- **Public リポジトリにコミットして良いデータ**：
  - データモデルの定義（本ドキュメント）
  - サンプルデータ（架空のレシピ名など）
  - コード（ロジック、テストなど）

### 実装での留意点
- 設定ファイルやログに data_source_id や実データを含めない
- テストデータはモック/ダミーデータを使用
- 本番データは Notion 上でのみ管理し、ローカルにキャッシュする場合も `.gitignore` で除外

## 5. M1実装に向けた準備

### M1で実装する機能（Read系）
- Recipes データソースからのレシピ一覧取得
- Meal Logs データソースからの直近履歴取得
- Rating による優先度づけ
- 直近抑制ロジックの適用

### 必要な API 呼び出し
1. **Recipes 取得**
   - `POST /v1/data_sources/{data_source_id}/query`
   - フィルタ: `Active = true` のレシピのみ取得
   - ソート: `Rating` 降順（高評価優先）

2. **Meal Logs 取得**
   - `POST /v1/data_sources/{data_source_id}/query`
   - フィルタ: `Date` が過去14日以内
   - レシピへのリレーション情報を取得

### M1の受け入れ条件との対応
- ✅ Recipes / Meal Logs の「必須プロパティ」と「型」と「用途」が明記されている
- ✅ 評価スケール（1〜5）、直近の定義（14日）、候補不足時の緩和方針（段階的緩和）が決まっている
- ✅ data_source_id 前提で後続 M1 が実装可能な状態（必要 ID・設定項目が確定）
