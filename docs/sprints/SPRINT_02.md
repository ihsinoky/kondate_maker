# Sprint 02 計画案（M1：9枠を実在URLで埋める）

## 1. Sprint Goal
外部ソース（白ごはん.com / Nadia / つくおき）から候補URLを取得し、
曜日ルール（水曜鯖・金曜スープ）を守ったまま、9枠を実在URLで埋める。

合格ライン：とにかく9枠がURLで埋まる（品質改善は次）

## 2. スコープ（In）
- URL候補取得（方式B）を実装し、候補プールを作る
- 9枠への割り当てロジックに候補プールを接続する
- 候補不足・取得失敗でも落ちない（警告＋フォールバック）
- キャッシュ導入（最低限）

## 3. スコープ外（Out）
- レシピ本文（材料・手順）の取り込み
- 買い出しリスト生成
- 自宅向け読み替え・分量換算
- Notion連携
- 過去レシピ検索

## 4. Sprint Backlog（提案：P0のみ）
### P0-1 取得・解析の実行場所を確定（CORS回避含む）
- 受け入れ条件：現行スタックに合わせて、候補取得がiPhoneでも動く

### P0-2 Nadia（りなてぃ）候補取得（最優先）
- タイトル＋URL＋時間文字列（取れる範囲で）を取得
- 受け入れ条件：候補が一定数取れ、割り当てに使える

### P0-3 つくおき候補取得
- 金曜スープ候補の安定化に寄与
- 受け入れ条件：候補が一定数取れ、スープ候補が不足しにくい

### P0-4 白ごはん.com候補取得（最低限）
- 旬食材（任意）をキーワードに候補を増やす用途
- 受け入れ条件：キーワード検索で候補URLが取れる

### P0-5 候補プールキャッシュ
- 受け入れ条件：毎回フル取得せずに再生成できる（更新は手動または一定時間）

### P0-6 9枠の埋め込み接続
- 水曜夜：設定鯖候補
- 金曜夜：スープ優先（候補不足なら警告）
- 他：一般候補から埋める（重複は許容しつつ、可能なら避ける）
- 受け入れ条件：9枠が実在URLで埋まり、Notionコピーにも反映される

## 5. デモ手順（PO確認）
1. iPhoneでアプリを開く
2. 「献立を作る」を押す
3. 9枠がすべて「タイトル＋URL」で埋まる
4. 水曜は鯖候補から選ばれている
5. 金曜はスープになっている（不足時は警告が見える）
6. 「Notionに貼る用にコピー」→ Notionへ貼る

## 6. リスクと回避
- 外部取得失敗：部分結果で埋める／警告
- 取得が遅い：キャッシュ優先／取得件数の上限
- 解析が壊れる：一覧ページ中心、抽出ロジックを最小化
