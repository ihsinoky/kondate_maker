# ユニットテスト

献立メーカーのユニットテストドキュメント

## 概要

このプロジェクトには、主材料推定、部分再生成、フィルタ動作の回帰を防ぐためのユニットテストが含まれています。

## テスト実行方法

### すべてのテストを実行

```bash
npm test
```

### 個別のテストを実行

```bash
# 主材料推定テスト
npm run test:main-ingredient

# 週状態・部分再生成テスト
npm run test:weekly-state

# フィルタ動作テスト
npm run test:filter-behavior
```

## テストファイル

### 1. 主材料推定テスト (`src/lib/mainIngredientEstimator.test.ts`)

**テスト数**: 35テスト

**目的**: レシピタイトルから主材料（タンパク質）を正確に推定できることを保証

**テスト内容**:
- 各主材料カテゴリの検出
  - 豚肉（3テスト）
  - 鶏肉（4テスト）
  - 牛肉（3テスト）
  - ひき肉（4テスト）
  - 魚（5テスト）
  - 卵（4テスト）
  - 豆腐（3テスト）
  - 厚揚げ（2テスト）
  - その他（4テスト）
- エッジケース（空文字列、野菜のみのレシピ）
- 検出優先順位（ひき肉 > 特定の肉類）
- getAllMainIngredients関数のテスト

### 2. 週状態・部分再生成テスト (`src/lib/weeklyState.test.ts`)

**テスト数**: 12テスト

**目的**: 週状態の永続化とロック機能が正常に動作することを保証

**テスト内容**:
- 週キー計算（月曜始まりの週）
- 保存・読込機能
  - 献立スロットの保存
  - 買い物リストの保存
  - 完全な週状態の保存
- クリア機能
- **ロック枠の保護**（部分再生成時に変更されないことを確認）
- バリデーション
  - 無効なJSON処理
  - 必須フィールドの検証
  - スキーマバージョンの検証
  - 不正な配列型の処理

### 3. フィルタ動作テスト (`src/lib/filterBehavior.test.ts`)

**テスト数**: 15テスト

**目的**: 主材料フィルタの優先挙動と候補不足時の緩和を保証

**テスト内容**:
- **主材料フィルタによる絞り込み**
  - 豚肉フィルタ（3件抽出）
  - 鶏肉フィルタ（2件抽出）
  - 牛肉フィルタ（1件抽出）
- **候補不足時のフィルタ緩和**
  - 候補が0件の場合の全プールへのフォールバック
  - 緩和時の警告フラグ設定
- **ロック枠の保護**
  - 部分再生成時にロック枠が変更されない
  - ロック枠のレシピが新規選択から除外される
- **重複レシピの回避**
  - 使用済みURLの追跡
  - スロット間での重複防止
- フィルタ一貫性の検証
- 空プールの処理

## テストデータ

各テストファイルには、実際のレシピタイトルに基づいたテストデータが含まれています：

### 主材料推定テストのデータ例
- `豚の生姜焼き` → `豚肉`
- `鶏の唐揚げ` → `鶏肉`
- `ハンバーグ` → `ひき肉`
- `鯖の味噌煮` → `魚`
- `野菜炒め` → `その他`

### フィルタ動作テストのモック候補プール
- 豚肉レシピ: 3件
- 鶏肉レシピ: 2件
- 牛肉レシピ: 1件
- ひき肉レシピ: 2件
- 魚レシピ: 2件
- その他: 4件

合計14件のダミーレシピでフィルタ動作をテスト

## CI統合

テストはGitHub ActionsのCIワークフローに統合されています：

```yaml
- name: Run tests
  run: npm test
```

lint、build前にテストが実行され、回帰を早期に検出します。

## テスト追加ガイドライン

新しいテストを追加する場合：

1. 適切なテストファイルを選択または新規作成
2. TestCaseインターフェースに従ってテストケースを定義
3. `testCases.push()` でテストケースを追加
4. `npm test` で動作確認
5. エラーメッセージは日本語または英語で明確に記述

## トラブルシューティング

### テストが失敗する場合

1. エラーメッセージを確認
2. 該当のテストファイルを個別に実行して原因を特定
3. mainIngredientEstimator.ts や weeklyState.ts の変更がテストの前提を壊していないか確認

### 新しいテストパターンが必要な場合

既存のテストファイルを参考に、同じ構造でテストケースを追加してください。
